# Merkavania: Level Design (Tiled conventions)

The map validator (`npm run validate:maps`) enforces everything here. Ids must match `src/data/` and `GAME_DESIGN.md`.

## Files
- One folder per biome: `public/maps/<biome>/`
  - `<biome>.world`: a Tiled world file listing every chunk and its pixel offset
  - `<biome>_x<XX>_y<YY>.tmj`: chunk maps, JSON format, zero-padded coordinates
  - `*.tsj`: external tilesets in JSON (never embedded in maps). The tileset `name` must be the asset-manifest key of its image.
- `public/maps/shared/elevation.tsj` (`tiles_elevation`) is the elevation tileset every biome uses: levels 0–3, then ramps and steep ramps for low levels 0–2 in each direction. It and the test terrain tileset are generated by `npx tsx scripts/gen-placeholder-tiles.ts`; append new tiles at the end so existing gids stay valid.
- `public/maps/test/test.world` is the 4×3 sandbox. Chunks x00–x01 are the M1 tank-feel room, with the start spawn at (480, 408). x02–x03 hold a level-1 plateau with a ramp north, a level-2 shelf behind a steep ramp east, and patches of road, rock, water, mud, rubble and minefield. Row y02 is the M4 progression gallery, entered through a gap in x00_y01's bottom wall: a depot, the mortar, dozer, armor plate and ammo rack pickups, a boulder and a rubble-choked corridor east (x00), a mortar switch on a rock-marked level-1 shelf that opens a door (x01), a cannon switch and its door (x02), and a repair kit at the end (x03).
- `public/maps/desert/` is the vertical slice: 18 chunks on a 5×4 grid (no x00_y00 or x00_y03). It is **built**, not edited in Tiled (see Built maps below); `desert.tsj` (`tiles_desert`) comes from `npx tsx scripts/gen-desert-tiles.ts`.
- Chunk size is fixed at **30×17 tiles** of 16px (480×272). World offsets must be multiples of the chunk size.
- Chunks that connect across biomes use an `exit` object pointing to the target biome, chunk and spawn.

## Built maps (`maps-src/`)
A biome under `maps-src/<biome>/` is written as one TypeScript layout per chunk (`x02_y01.ts`, typed by `scripts/mapLayout.ts`) and turned into the Tiled files by `npm run build:maps` (`scripts/mapBuild.ts`, with tests). Edit the layout, rebuild, then run `npm run validate:maps`; a test fails if the committed `.tmj` files are stale. The built files still open in Tiled for viewing, but changes made there are overwritten by the next build.
- `ground`: 17 strings of 30 characters from the biome's legend. Desert: `.` sand, `,` packed sand, `=` road, `r` rock, `%` rubble, `c` crawlspace; walls (solid) `#` rock, `B` concrete, `S` sandbags.
- `elev`: `0`–`3` (or `.` for 0) are levels; `n`/`e`/`s`/`w` are ramps going **up** that way, upper case for steep. A ramp's level is the level behind it (or one below the level in front of it, following a run of ramp cells), and the two must agree.
- `decor` / `above` (optional): desert decor `t` tyres, `x` crate, `o` barrel, `b` scorch mark, `k` sign, `W` 2×2 wreck; above `N` camo net. `.` is empty.
- `objects`: helpers in tile coordinates (points land on tile centres): `spawn`, `depot` (a 32×32 pad on the tile corner), `pickup`, `enemy`, `path` (a patrol or rail polyline), `destructible`, `boulder`, `lever` (a switch), `door`, `radio`, `zone`, `boss`.
- The builder shades ground lighter per level, draws a rim and cliff face on the edges of higher ground and an arrow overlay on ramps (red hazard chevrons on steep ones), all on the `walls` layer as non-solid tiles, and scatters small decor on plain sand from a seed (so rebuilds are identical).

## Layers (per chunk, in this order)
| Layer | Type | Purpose |
|---|---|---|
| `ground` | tile | Base terrain; tiles carry a `terrain` property |
| `elevation` | tile (invisible) | Height data: `level` and `ramp`/`steep` properties |
| `walls` | tile | Solid tiles and cliff faces (tile property `solid: true`) |
| `decor` | tile | Non-colliding detail below entities |
| `above` | tile | Drawn above entities (tree canopies, bridges, overhangs) |
| `objects` | object | Everything interactive (see below) |

## Tile properties
| Property | Values | Meaning |
|---|---|---|
| `terrain` | `sand`, `rock`, `road`, `water_shallow`, `water_deep`, `mud`, `rubble`, `minefield`, `crawlspace`, `chasm`, `missile_zone` | Movement rules / gates |
| `level` | `0`–`3` | Elevation of the cell (on `elevation` layer; an empty cell is 0). For a ramp, its **low** end |
| `ramp` | `n`, `s`, `e`, `w` | Direction you travel to go **up** the ramp, which climbs exactly one level |
| `steep` | `true` | Ramp needs `suspension` (Mk3+) |
| `solid` | `true` | Blocks movement and direct fire |
| `cleared` | tile id | On a gated ground tile (rubble): the tile from the same tileset to show once the player has the terrain's ability |

Terrain → requirement mapping (defined in `data/terrain.ts`):
`water_deep`→`snorkel`, `mud`→`wide_tracks`, `rubble`→`dozer_blade` (clears it), `minefield`→`mine_plow`, `crawlspace`→scout only, `chasm`→drone only, `missile_zone`→`trophy` (otherwise heavy damage over time).

## Object types (`objects` layer; the Tiled object *class/type* is the id)
| Type | Properties | Notes |
|---|---|---|
| `spawn` | `name` | Named entry point; `start` is the new-game spawn |
| `exit` | `toBiome`, `toChunk`, `toSpawn` | Cross-biome transition |
| `depot` | `id` | Repair/save pad: a rect, or a point for a 32×32 pad. Driving onto it heals, rearms and saves |
| `pickup` | `ability` or `minor`, `id` | Persistent once collected |
| `mk_upgrade` | `tier` | Usually spawned by the boss's death |
| `enemy` | `enemyType`, `level`, optional `patrol` (polyline name) | Point object; its rotation is the facing (static guns only traverse around it). A `rifle_squad` spawns three soldiers |
| *(untyped polyline)* | `name` | Patrol path for an enemy in the same chunk; the route loops |
| `boss` | `id`, `bossType`, `arena` (name of a `boss_arena` zone), `rail` (name of a polyline) | Point at the boss's centre. Entering the arena wakes it; its gun slides along the rail. Persistent once beaten, and it leaves an `mk_upgrade` crate for its reward tier |
| `destructible` | `material`: `sandbag`/`wood`/`concrete`/`armored`, `id` | Persistent |
| `boulder` | `id` | Shoved by a tank with `dozer_blade`; goes back to its spot when its chunk reloads |
| `switch` | `id`, `activatedBy`: `cannon`/`mortar`/`scout`/`drone`/`lahat`/`remote` | Persistent. `cannon` takes a hit from the player's main gun, `mortar` a mortar blast (either works on any level the shell reaches); the others arrive with their pawn or missile |
| `door` | `id`, `opensWith` (switch id) | A rect. Blocks movement and fire on its level (and fire from below) until its switch is flipped; stays open after |
| `zone` | `kind`: `sensor`/`boss_arena`/`radio_trigger`, props per kind | Rect objects |
| `radio` | `id`, `messageKey`, `once` (default true), `speaker` (`command` default, or `unknown`) | Point (within 24px) or rect trigger; plays when the active pawn enters. A `once` radio is saved as heard. Overlapping radios play in map order |

Every object that has persistent state needs an `id` that is unique within its chunk. The save key is `<chunkId>:<id>`.

## Design rules
- **Telegraph gates:** every gate type has a distinct tile or sprite (cracked concrete, a mine sign, a deep-water colour), and the player should see one before getting the ability for it.
- **Depots:** a depot within about 4 chunks of travel of any point, and one before every boss.
- **No soft-locks:** the player must never be able to reach a spot they can't leave with their current abilities. One-way drops are allowed only if the area below has another way out.
- Keep the chunk edges that line up between neighbours consistent: matching elevation levels and matching walls.
- Leave space for a 32px tank to turn. Corridors should be at least 3 tiles wide for the tank, and 1 tile wide for `crawlspace`. Ramps also need to be at least 3 tiles wide, because a body may never straddle a cliff.

## What `validate:maps` checks
The rules are in `src/logic/world/validate.ts` (rule 6 in `reachability.ts`); `scripts/validate-maps.ts` only reads the files. Rules 1–5 have been live since M2, and rule 6 since M4.
1. Every chunk listed in a `.world` exists, is named after its position, is 30×17, and has the required layers in order, with `elevation` hidden.
2. All tilesets are external `.tsj` named after a manifest image with the same file, every `terrain`/`level`/`ramp`/`steep`/`solid` value is known, and every tile gid belongs to a tileset.
3. Every object type and its properties are known (ability, minor pickup, tier, material, `activatedBy`, zone `kind`, enemy and boss types, radio speakers and message ids exist in `src/data/` and `src/i18n/en.json`; a radio's `once` is a boolean).
4. Persistent object ids (bosses and radios included) are unique per chunk, doors are rects whose `opensWith` points to a switch in the same chunk, enemy `patrol` and boss `rail` name a polyline in the same chunk, a boss `arena` names a `boss_arena` zone rect in the same chunk, and exits point to existing biomes, chunks and spawns.
5. Neighbouring chunks agree on elevation where they meet: facing cells are on the same level or joined by a ramp, unless either one is solid.
6. **Progression reachability:** starting at `start` with Mk2 and no abilities, it floods the cells the tank can enter (`canEnter`, with closed doors solid), takes every pickup and `mk_upgrade` it reaches (an upgrade grants its tier's signature ability), beats every boss it reaches (which grants its reward tier's signature ability), plus, once it has `hatch_scout`, every pickup the scout can walk to from there (crawlspaces included), flips every switch it can activate, which opens its doors, and repeats until nothing changes. A `cannon` switch needs a reached cell on its level within the 105mm's range and in line of sight; a `mortar` switch needs the mortar and a reached cell within its min..max range; a `scout` switch needs `hatch_scout` and a scout's path (crawlspaces included) from a reached cell. Other switches never count yet. Every pickup, depot, boss, `mk_upgrade` and radio left unreached is reported, which also catches an ability locked behind itself. It works per cell, so it doesn't know the tank is two tiles wide, and it only runs on a world that has `start`.

Failures print `<file>:<layer>:<object>` plus a reason. The command exits non-zero, which fails CI.
